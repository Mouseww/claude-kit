# Docs Automation

> How indexes, dashboards, and doc hygiene become machine responsibilities.
> This is the Layer 1 + Layer 3 reference: frontmatter schema, generated files, the docs linter, and CI gates.

## Why

In a team, any file that every feature must edit is a guaranteed merge conflict and a guaranteed drift point. The solo harness had four of them: `product-specs/index.md`, `design-docs/index.md`, `tech-debt-tracker.md`, `QUALITY_SCORE.md`. Fleet engineering replaces all four with per-document files plus generated aggregates. Humans and agents write only leaf documents; a script writes everything that summarizes them.

The same principle the codebase already follows (formatting enforced by formatter, architecture enforced by tests) applied to documentation: **anything about docs that can drift gets a mechanical check.**

## Frontmatter Schema

Every document under `docs/` (except generated files and `references/`) starts with YAML frontmatter:

```yaml
---
type: product-spec | design-doc | exec-plan | tech-debt | quality-area
title: Order Auto-Archive
status: Draft | In Review | Approved | Active | Completed | Superseded | Archived
owner: axel_feng            # who answers questions about this doc
ticket: PIEX-5336           # ticket-system ID; fallback {YYYYMMDD}-{author}-{slug}
created: 2026-06-12
updated: 2026-06-12         # bump on every meaningful edit
relates:                    # optional links to sibling docs
  - docs/product-specs/order-archive.md
---
```

Type-specific extra fields:

| Type | Extra fields |
|------|-------------|
| exec-plan | `claims:` (code/docs glob lists; see collaboration-controls.md) |
| tech-debt | `priority: P1/P2/P3`, `area:`, `resolved:` (date, when closed), `pr:` (link) |
| quality-area | `area:`, `score: A-F`, `reviewed: YYYY-MM-DD` |

Frontmatter is the single machine-readable source. Status lives ONLY here, not duplicated in body tables.

## Generated Files: never hand-edit

| Generated file | Source |
|----------------|--------|
| `docs/product-specs/index.md` | frontmatter of `docs/product-specs/*.md` |
| `docs/design-docs/index.md` | frontmatter of `docs/design-docs/*.md` |
| `docs/exec-plans/index.md` | frontmatter of `active/*.md` + `completed/*.md` |
| `docs/tech-debt/index.md` | frontmatter of `docs/tech-debt/TD-*.md` |
| `docs/QUALITY_SCORE.md` | frontmatter of `docs/quality/*.md` |

Each generated file carries a banner: `<!-- GENERATED by tools/docs_lint.py - do not edit by hand. Run: python tools/docs_lint.py --fix -->`.

Three layers keep them honest:

1. **Feedforward**: the banner tells agents and humans not to edit.
2. **Hook**: the repo's `.claude/settings.json` PreToolUse hook blocks Claude Code from Write/Edit on generated paths, with a self-healing message pointing at `--fix` (see `templates/block-generated-docs.py.tpl`).
3. **Feedback**: CI runs `docs_lint.py --check`, which regenerates in memory and fails on any diff.

## The Docs Linter (`tools/docs_lint.py`)

Checked into the project repo at `tools/docs_lint.py` (template: `templates/docs_lint.py.tpl`). Two modes:

### `--fix` (local, before every docs commit)

- Regenerates all index files and `QUALITY_SCORE.md` from frontmatter

### `--check` (CI gate + pre-audit)

| Check | Failure it prevents |
|-------|---------------------|
| Frontmatter present, fields valid, status in allowed set per type | Untracked / unclassifiable docs |
| Generated files match regeneration | Stale or hand-edited indexes |
| Relative links resolve | Broken navigation for agents |
| Plan in `completed/` has status Completed; plan in `active/` has status Draft/In Review/Active | Lying lifecycle state |
| Claims overlap between active plans | Two plans silently working the same code |
| Staleness: active plan `updated` older than N days (default 21) | Abandoned plans holding locks |
| Tech debt: P1 entries older than M days (default 30) unresolved | Critical debt rotting silently |
| Duplicate ticket IDs across plan files | Same ticket planned twice |

Exit code 0 = clean (warnings allowed for staleness/overlap if configured); non-zero with self-healing messages otherwise. Every failure message states the file, the rule, and the exact command or edit that fixes it.

## CI Doc Gates

The stack CI template (`stacks/{stack}/templates/ci-workflow.yml.tpl`) adds two jobs beyond build/test/format:

1. **docs-lint**: `python tools/docs_lint.py --check` on every PR.
2. **plan-reference gate**: for branches matching `feature/{TICKET}-*`, verify `docs/exec-plans/active/{TICKET}-*.md` exists on the target branch (i.e., the docs-first PR merged before this implementation PR). Docs-only branches (`docs/*`) and fix branches are exempt by pattern. Failure message explains the docs-first rule and how to comply.

## Scheduled Sweeps (Layer 3 garbage collection)

Some checks are warnings on PRs but become actionable on a schedule. Run weekly/monthly (CI cron or a scheduled agent):

| Cadence | Sweep |
|---------|-------|
| Weekly | `docs_lint.py --check --strict-stale`: stale active plans, overdue P1 debt, claim overlaps -> post report to team channel or open a ticket |
| Monthly | Quality dashboard review: areas scoring C or below get a ticket; areas not reviewed in 90 days get re-audited |
| Quarterly | CODEOWNERS accuracy, golden rules review, prune Superseded docs to `Archived` |

## What Stays Manual (deliberately)

- **Writing leaf documents**: specs, designs, plans, debt entries, quality scores are authored by people/agents; only aggregation is automated.
- **Semantic doc review**: the linter proves a doc parses and links; only the doc owner can prove it is true. That is what CODEOWNERS routing is for.
- **Claim arbitration**: the linter detects overlap; humans decide the outcome.
